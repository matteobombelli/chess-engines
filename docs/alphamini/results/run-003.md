# AlphaMini Run 003 — published v1 result

Status: **complete**. Run 003 is the deployed v1 lineage terminal. It reached the
precommitted 72-hour cumulative active-compute target and produced the model now
served in production.

The authoritative generated reports and ledgers live outside Git under
`runs/alphamini-run-001`, `runs/alphamini-run-002`, and `runs/alphamini-run-003`.
Identity hashes, per-phase active-time accounting, and loss curves are read from
those immutable records, not from this summary.

## Reproducibility identity

- Lineage: `run-001 -> run-002 -> run-003`, weights-only forks. Each fork carries
  gradient history in the weights alone; optimizer, replay, and sampler state do
  not cross a fork boundary.
- Run/config/semantic hashes, source commit, clean-worktree status, and both lock
  hashes: recorded per run in the ignored run ledgers.
- Hardware: one NVIDIA GeForce RTX 3070, 8 GiB, as in every prior AlphaMini run.
- Active compute by phase: recorded per cycle in the ledgers; only the aggregate
  active totals are reproduced below.
- Final budget milestone: 259,533 s cumulative active compute against a 259,200 s
  (72-hour) target, a 0.13% overshoot. An external watcher stopped the run at the
  target; the overshoot is the granularity of the cycle boundary, not a budget
  extension.

## Lineage and active compute

| Run | Relationship | Cycles | Active compute | Outcome |
|---|---|---:|---:|---|
| run-001 | fresh from random M0 | 50 | 37,252 s (10.35 h) | Interrupted |
| run-002 | weights-only fork of run-001 | 4 (failed) | 2,723 s (0.76 h) | Failed at export |
| run-003 | weights-only fork of run-002 | 339 | 219,558 s (60.99 h) | Complete |
| **Cumulative** | | | **259,533 s (72.09 h)** | Target met |

Run 002 was intended to relax the ONNX export parity tolerance, but its fork was
seeded with an unedited copy of the parent configuration, so `parity_atol`
remained `1e-4`. It failed at the cycle-4 ONNX export when `max_abs_policy`
reached `5.5e-4`, above that tolerance. The failure is recorded rather than
relabeled: the configuration did not carry the change its reason string claimed.
Run 003 forked run-002 with `parity_atol = 1e-3` and exported cleanly from then
on.

Because the forks are weights-only, the 72-hour figure is cumulative active
compute across the whole lineage, not the wall time of run-003 alone.

## Run incidents

All incidents were recovered through the ordinary ledger path with no data loss
and no manual edits to a run directory.

- Intermittent CUDA out-of-memory during self-play collection at cycles 243, 261,
  264, 306, and 309. Each self-healed through a driver-level relaunch.
- One host reboot, recovered with `recover` followed by `resume`. Active-time
  accounting was preserved across the restart, so the budget total remains exact.
- One host disk-full condition, resolved by `alphamini-train gc --apply`, which
  purged about 275 GB of stale tensor caches. Those caches are re-materializable
  from the committed collection shards, so the purge removed derived data only.

## Calibration and claims

Measured 2026-08-25 with the same method and sealed-artifact discipline as the
published `MinimaxDepth3V1` calibration.

- **Chess.com 30+0 move-quality equivalent: 1969.** The 95% whole-player
  bootstrap interval runs from **1758 to at or above 1999**; the upper endpoint
  is censored by the predeclared calibration range and must not be read as
  exactly 1999.
- Primary regression R² 0.780, from 1,921 analyzed positions across 1,742 games.
- Corpus `data/chesscom-30-0-refined.jsonl`; calibrate v2 sealed artifacts;
  Stockfish 17.1 at 100,000 nodes; sample seed 1; three positions per player and
  one analyzed position per player; four player-disjoint shards.
- AlphaMini played at its production serving limits: 9,000 ms, a 10,000-simulation
  cap, batch 8, on CPU.

An independent high-rating supplement checked the upper half of the interval.
Using `data/chesscom-30-0-very-high.jsonl` with `--min-rating 1700`, and
excluding every human already present in the main corpus, 116 positions gave an
estimate of 1904 with the human and bot loss curves crossing in the same
1800–1999 band. The two samples agree.

Exact-human-move agreement on the shared corpus:

| Engine | Exact agreement |
|---|---:|
| Timed minimax | 37.0% |
| MinimaxDepth3V1 | 36.9% |
| AlphaMini | 34.4% |
| Random | 4.8% |

Agreement is reported as context, not as the estimate. AlphaMini agrees with the
human move slightly less often than either minimax while calibrating higher,
because the estimate is fitted on evaluation loss rather than move identity: the
moves it does not share with the human are on average cheaper ones.

Keep the three Elo concepts separate. This is a historical-position move-quality
estimate. It is not an internal ladder rating, not a full-game arena rating, and
not a rating earned by playing complete games on Chess.com. The deployed label is
"≈1970 Elo".

## Limitations

- One training seed and one consumer GPU.
- Current-state encoder omits history and the last-move cue.
- No resignation, so dead-lost games consume throughput. No resignation
  diagnostic data exists in v1.
- Fixed PUCT rather than a scheduled or Gumbel policy.
- The lineage crosses two weights-only forks, so no single optimizer trajectory
  spans the full 72 hours.
- The Depth-3 rung is unfinished, so there is no full-game result against any
  frozen opponent.
- Results do not transfer automatically across Elo pools or time controls.
